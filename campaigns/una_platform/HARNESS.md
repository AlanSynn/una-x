# Harness implementation contract and negative tests

The prior benchmark/test files are historical inputs to audit, not trusted launchers. HARNESS
must make the entire new campaign relocatable and installed-path truthful before new evidence.
Own new benchmarks/platform and tests/platform_harness; modify old tests only through reviewed
portable-path fixes, never their committed evidence/goldens. A clean baseline checkout remains
read-only; all output/cache/temp paths are explicit campaign-owned directories outside source.

## One real job
Resolve installed import roots and expected wheel/source/kernel hashes before execution.
Construct Settings/ExecutionOptions from a frozen manifest. Dispatch the actual requested public
API: accessibility, ODM, chosen flow model, Madina method/workflow or public RunBatch. Assert
expected engine/model/profile and substantive backend counters in a separate engagement leg.
Call the public API once. Do not pre-resolve gravity cap or construct a second engine and call
that a production timing. Required read/prepare/compute/export synchronization is within wall.
Time process launch/import/JIT/cache attach and post-run hashing separately and also report the
full launch-to-validated-completion boundary. Never claim fsync durability from Python close alone.

## Batch run
Use the PUBLIC RunBatch path when that is the treatment, not only an external pool. External
independent-job throughput is separately labeled. Readiness, startup, warmup, dispatch, successful
completion and shutdown are separate boundaries. Failed/cancelled/missing outputs invalidate a
qualification window. Count validated successes / actual wall, not submitted jobs / wall.
Parent drains results concurrently with bounded job submission and watches child exit codes.
No variable-size queue or all-in-memory output list can escape the resource plan.

## Measurement records
Every session includes: full source/reference/packet/wheel/kernel hashes; model+profile; input
and settings fingerprints; workload class; output obligations; requested AND effective backend;
CPU threads and separate pools, physical versus logical stripes; device capability/runtime;
cache state/hits/misses/producer counts; compile/import/packing/transfer/kernel/sync/export/hash
and whole-job/batch times; sampled process-tree/device peaks, sampling interval, filesystem;
completed/failed/cancelled counts; fault/timeout/OOM status; environment and raw file manifest.
Do not label effective P-core affinity if only a worker-count cap was set on a heterogeneous CPU.

## Memory and thermal sampling
A coordinator sampler sums simultaneous parent+recursive descendant RSS (and PSS/USS where
available with definitions), tracks available RAM/swap/disk/device allocation, and records
sampling loss/child exits. Per-worker maxima alone are not the simultaneous whole-pool peak.
Do not sum noncoexisting maxima. Include native/runtime queues and retained device contexts.
Warm windows are long enough to detect sustained pressure and thermal drift; cool/order-control
before paired runs, not a post hoc removal of slow candidate samples.

## Validation isolation
Baseline determinism first. Compare arrays bitwise before export quantization. Validate artifact
set/schema/row/CRS/numerical bytes and geometry as declared. Timestamp/RNG normalization is
specific and controlled; no blanket remove-metadata. State traces instrument diagnostic runs
only, with source bindings proving same semantic kernel as timed execution. A passing file-hash
comparison without proving both arms executed different intended implementations is insufficient.

## Required harness mutants
1. --analysis flow invokes accessibility: must fail model/engine assertion.
2. Source checkout shadows installed wheel: must fail identity.
3. CPU fallback reported native/GPU: must fail engagement.
4. Missing output, empty comparison sets or failed job counted as success: must fail.
5. Wrong workload hash/changed profile or dtype: must fail before timing.
6. Child dies with full queues: bounded fail and cleanup, no deadlock.
7. Reused output directory or test writes committed evidence: fail safety guard.
8. Parent memory only, omitted device transfers, unsynchronized result: fail measurement audit.
9. Baseline oracle generated by candidate or reused only by output filename: fail provenance.
10. Increasing max queue/workers while claiming same CPU/RAM policy: fail resource ledger.

## Custody and reuse
New raw session JSON/JSONL and exact command files are append-only per unique run ID. Reuse
requires unchanged dependency closure (code/reference/profile/hardware/compiler/workload/harness).
Do not re-run the whole suite after docs-only edits. Do not accept old missing raw session bytes
as reproducible evidence. Use compression and a bounded corpus, not evidence deletion.
