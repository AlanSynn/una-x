# D12: Differential science, multi-city performance and final composition

## Reference matrix
UNA legacy -> current-main independent baseline; Madina legacy -> pinned working Madina
reference (or separately recorded dependency-only bridge); corrected_v1 -> independently
reviewed corrected CPU reference. Backend/reference comparisons use identical profiles/models,
input order and reduction plans. Legacy-vs-corrected output differences are bug deltas.

L0 exhaustive tiny graph/state/bit cases, L1 actual kernel plus ABI, L2 real public path and
chronology, L3 observed multi-city calibration, L4 actual user target only when supplied.
Use exact bytes for finite values and signed zero, nonfinite masks and payloads where required,
IDs/row order/categorical outputs, all logical-step state and output schemas. Add deliberate
mutants to demonstrate the test catches swapped closest-facility direction, missing paths,
wrong cache identity, lost reset, changed reduction partition and fake backend engagement.

## Workloads
Audit current observed-network catalog, do not claim purged raw sessions exist. Freeze at least
three public/license-cleared morphology scenarios when accessible (dense connected mesh,
sparse/disconnected/cul-de-sac, irregular/high-degree/duplicate/turn-sensitive). Named city is
metadata, not a causal property. Keep one morphology held out from tuning. If actual reported
failure data absent, label mechanism reproductions synthetic and incident unresolved.

Cross dimensions deliberately: network extent, destination density, local radius/detour, origins,
output formats, model, cold/warm/cache states. A transformed small selection fixture is not
production L4. Freeze full logical domain and row order for each arm; cannot shrink it on OOM.

## Measurement
Use corrected HARNESS behavior and BENCHMARKS.md boundary. Installed public single call and
public RunBatch are primary. Compare reference vs improved CPU, same algorithm native, same
algorithm GPU, cache-off/on and serial/parallel as separate factors before composed wins.
Record successful validated jobs/time, source/wheel/kernel hashes, CPU/device budgets, actual
pools/stripes, transfer/conversion/setup/sync, simultaneous host/device memory and output I/O.
Profiler traces explain work; final timing is uninstrumented with checks outside or separately
charged as declared. Failed/hung reference is censored, never infinite-speedup arithmetic.

## Final composition
Preserve independent branch experiments and integrate one reviewed closure. Re-run cross-feature
checks after cache/batch/backend/science interactions change. Freeze final source, devices,
profiles, workload manifests, selector qualification and binaries before paired confirmation.
Retain compact decisive raw samples/logs and representative outputs, not only hashes of deleted
files. REVIEW verifies arithmetic from raw records and default-route actual engagement. CLOSE
writes supported/unsupported capability matrix, incident report, bug ledger, scoped performance
frontier, bitparity matrix, exact merge manifest and explicit unavailable gates.

No full success until required API/native/GPU/batch/cache/science gates actually pass. A correct
partial implementation is still partial. A fast synthetic kernel is still not the requested end-to-end result.
