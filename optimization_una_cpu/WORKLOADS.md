# Workloads

## W0 adversarial synthetic
Tiny graph families for exhaustive row order, duplicates, self-loops, isolated nodes, unusual float bit patterns, empty arrays, strided/read-only/wrong-dtype inputs, and fallback admission.

## W1 small genuine
Create or select a tiny real geospatial network/origin/destination fixture that exercises file loading, CRS, topology, snapping, accessibility, gravity metrics, and all required output formats. Include an elevation case and obstacle case where practical. Add a flow case using automatic gravity-cap derivation to verify cross-phase dependency.

## W2 tutorial proxy
When no user target is supplied, use a pinned subset or complete appropriate tutorial workflow/data from the audited upstream repository. Record source URLs/SHAs, exact file hashes, Settings, outputs, and why it is representative. Label every performance conclusion proxy-qualified.

## W3 medium selection
A genuine workload large enough that CSR/search/export contributions are stable and concurrency tradeoffs appear, but still within bounded laptop development budget. Freeze before candidate timing.

## W4 actual target
User's real dataset, Settings, job count, outputs, resource budget, and throughput target. Currently unavailable. Do not invent or replace it with W2/W3.

Never reduce origin/destination/edge count or output obligations inside a frozen workload arm to improve candidate timing.
